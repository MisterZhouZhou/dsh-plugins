# dsh-plugins Repository Instructions

This repository is a monorepo of DeepSeek Harness Web GUI plugins. Each plugin is an independent Cordis bundle mounted through `cordis.patch.yml` and profiles. Never modify a DSH source checkout.

## Repository Layout

- `packages/` — feature plugins, each a scoped npm package with `dsh.bundle.patch` and `dsh.client` declarations.
- `shared/` — cross-package shared build presets (`tsdown.client.ts`, `web-platform.ts`) and runtime source modules. Package copies are generated by `sync-shared.mjs` and must not be edited manually.
- `scripts/` — repository maintenance tools: plugin scaffolding, shared-file sync, dev watcher, PR review.
- `docs/` — long-lived documentation.
- `.github/` — CI workflows, PR template, issue templates.

## Common Commands

```sh
pnpm install
pnpm build
pnpm dev:watch          # watch-rebuild browser bundles; dsh web host reloads the GUI automatically
pnpm test
pnpm typecheck
pnpm test:scripts
node scripts/dsh-plugin-new <name>

# Before merging:
pnpm typecheck && pnpm test
```

## Repository Rules

- Mount plugins only through `cordis.patch.yml` and profiles. TypeScript configuration must not reference a DSH checkout; use official `@deepseek-ai/*` SDK packages from `node_modules`.
- New packages use the `dsh-` prefix and an npm scope.
- Use `shared/tsdown.client.ts` for client UI bundles; do not copy the build preset into a package.
- Keep `NPM_TOKEN` in the environment. Store token configuration in the user `~/.npmrc`; the project `.npmrc` should contain only scope mappings.
- Plugin package READMEs require English and Chinese (`README.md` + `README.zh.md`).
- Keep each fact in its owning document. Update documentation when behavior changes.

## Package Anatomy

Each plugin package follows this layout:

```
packages/dsh-<name>/
├── src/
│   ├── index.ts           # host entry (apply function)
│   ├── mount-once.ts      # deduplication guard
│   ├── host/              # host-side code (runs in DSH host process)
│   └── client/            # browser-side code (UI)
├── tests/
├── package.json           # dsh.bundle + dsh.client declarations
├── cordis.patch.yml       # plugin row insertion
├── tsconfig.json
├── tsdown.config.ts       # uses shared clientBundle preset
├── vitest.config.ts
├── README.md / README.zh.md / README.i18n.yaml
└── AGENTS.md (optional)
```

### Package Constraints

- **SDK only**: Types from `@deepseek-ai/*` devDependencies; declare peerDependencies for runtime services.
- **Build preset**: All tsdown packages import `shared/tsdown.client.ts`. Do not copy it into a package.
- **Host / client separation**: `src/index.ts` is the host half; `src/client/` is the browser half; `src/core/` is shared pure logic.
- **Exports**: `.` (host), `./client` (browser), `./src/*` (test references), `./package.json`.
- **Browser bundle purity**: `@deepseek-ai/*` value imports are forbidden in the browser half — collaborate through cordis services instead.

## Branches, Commits, and PRs

- `main` is the default branch. Rebase on `origin/main` before submitting a PR.
- Use Conventional Commits: `feat(scope)`, `fix(scope)`, `docs`, `test`, `refactor`, `chore`.
- PRs target `main`. Fill the PR template completely.

## Release

Releases are tag-driven. Verify every package version against the `vX.Y.Z` tag, and pass all gates (`pnpm typecheck && pnpm test && pnpm build`) before release.
